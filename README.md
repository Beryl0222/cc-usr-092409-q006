# 研学实操资源编排

跨馆实验的可恢复实操编排服务：把团组、活动槽、器材单元、耗材批次和学习证据串成一条只增事件链，在污染或校准失效时沿器材与样品接触链做局部隔离与恢复。

## 模块

- `src/validator.js`：基础事件信封校验（保持基线兼容）。
- `src/domain.js`：事件溯源领域内核（纯函数，无 I/O）。
  - `decide(command, state, now)` 做前置校验并原子产出事件；`applyEvent(state, event)` 归约状态；`replay(events)` 从日志完全重建。
  - 事件一经追加不可原地改写；更正只能产生后继记录。所有时间比较先转毫秒时间戳，避免不同时区偏移的 ISO 字符串字典序错误。
- `src/service.js`：`StudyTourService` 门面、离线回执队列、崩溃恢复与领队视图投影。
- `contracts/domain.schema.json`：领域事件类型、聚合类型与去重字段约定。
- `tests/orchestration.test.js`：重放污染发现与局部恢复完整过程的服务测试。

## 业务规则

### 确认即锁定（原子）

`confirmGroup` 一次同时锁定五项要素，任一不满足则整单不留痕：

1. 人数（正整数）；
2. 导师资格（对风险分组的资质在确认时刻有效）；
3. 仪器校准（确认时刻在有效期内）；
4. 耗材批次（所有活动槽合计需求不超过可用余量，只做预留不扣减）；
5. 风险分组（必选，并随每个活动槽锁定）。

### 开始后才扣减，未用预留原子释放给候补

- `ACTIVITY_STARTED` 之后 `issueConsumables` 才按实际领用把预留转为消耗，不能超预留、不能用已隔离批次。
- `releaseUnused` 原子释放未使用预留；同一次提交里按候补登记顺序、各自原截止点 `cutoff` 整单贪心满足候补（`WAITLIST_FULFILLED`）。
- 超过截止点仍等待的候补在收敛时终止（`WAITLIST_EXPIRED`）；依赖批次污染报废的候补同样终止。

### 污染/校准失效沿接触链局部处理

- `recordContact` 记录 `unit/batch/sample` 节点间无向接触边及发生活动槽。
- `raiseHazard` 从前组遗留样品等根节点沿接触链定位受影响仪器、批次、样品；同一批次被另一团组继续领用也会被定位。
- **只暂停未完成节点**：已完成活动槽与未受影响团组不动；仪器与批次进入隔离（`RESOURCE_QUARANTINED`、`SLOT_SUSPENDED`）。
- 恢复路线：`recordCleaning` → `CALIBRATION_RECERTIFIED`（也支持不经过清洁直接复检的路线）→ `SLOT_RESUMED`（可带批次替换）或 `proposeReplacement` 生成替代活动槽；替代活动必须给出 `equivalence_note` 说明与原目标的等价关系。

### 学习证据保留来源，失效须说明原因

- 暂停/替换边界之前合法采集的证据保持有效并可追溯 `source_ref`；边界之后采集的数据不能作为该槽证据。
- 受污染数据支撑的证据通过 `EVIDENCE_INVALIDATED` 显式失效并记录原因。

### 离线回执与服务恢复

- 离线领用回执带 `receipt_id` 与规范化内容指纹；完全重放时同标识同内容幂等、**不重复扣减**；同标识异内容不扣减、进入隔离（`RECEIPT_QUARANTINED`）。
- 同 `event_id` 异 `content_hash` 的事件进入隔离而不是覆盖既有状态。
- 崩溃后 `recover()` 仅凭事件日志完整重建（库存流水、接触链、改线、证据、隔离区、回执指纹一致），再按各候补**原截止点**继续候补与复检判定。

### 领队视图

`leaderView()` 回答三件事：

- 每次改线**保留了哪些节点**（`kept_nodes`、暂停/恢复/替代清单）；
- **哪些证据失效**（失效证据与原因；保留证据带来源）；
- **耗材余量为何变化**（每个批次的锁定、领用、释放、候补、替代、报废逐条流水与可用余量）。

## 本地检查

```bash
npm test     # node --test，重放完整污染发现与局部恢复过程
npm run build # 全部源文件语法检查
```

上述命令均在单个 Linux 应用容器内执行，不需要另行启动外部服务。
